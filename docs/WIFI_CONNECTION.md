# 荔枝派 Wi-Fi 连接与切换指南

适用设备：当前项目使用的 LicheeRV Nano Wi-Fi 版本。

目标：荔枝派与笔记本连接到可以互访的无线网络，使荔枝派只用充电宝供电时，也能通过 SSH 登录。

> 本文基于 2026-10-25 对当前设备的只读检查。已确认 USB SSH、无线网卡、SSH 服务和开机联网脚本正常；尚未执行切换到 C103 的操作，也未验证断开 USB 后的无线登录。更换系统镜像后，配置入口和命令可能不同。

## 1. 先理解供电、网络与 IP

- 充电宝只负责供电，不提供网络。
- USB 连电脑时，可以通过 USB 虚拟网卡 SSH 登录；拔掉 USB 后，这条网络会断开。
- 无线登录使用荔枝派的 **wlan0 地址**，不是原来的 USB 地址。
- 推荐两台设备连接同一个普通路由器或允许设备互访的手机热点。
- 同一个 Wi-Fi 不保证能够互访：访客网络、校园网络、客户端隔离、VPN 和防火墙都可能影响连接。
- 不要为了“同网段”随意填写静态 IP；优先由同一个路由器通过 DHCP 自动分配地址。

检查当时的网络情况如下，地址以后可能变化：

| 设备/接口 | 网络 | 当时的 IP |
|---|---|---|
| 笔记本 WLAN | C103 | 192.168.1.103 |
| 荔枝派 wlan0 | GDIP_WEB | 172.20.184.29 |
| 荔枝派 usb0 | USB 网络 | 10.133.125.1 |
| 荔枝派 usb1 | USB 网络 | 10.133.124.1 |

## 2. 保留 USB 连接，登录荔枝派

先将笔记本连接到目标 Wi-Fi，例如 **C103**，并保持荔枝派与电脑的 USB 数据连接。

在 **笔记本 PowerShell** 中执行：

```powershell
ssh root@10.133.125.1
```

登录后，下面第 3～5 节的命令都在 **荔枝派终端** 中执行，不要在 PowerShell 中直接执行。

> 如果摄像头或录像程序正在运行，先通过原启动终端正常停止，并等待清理结束，再调整网络。不要直接杀掉摄像头进程或拔电。

## 3. 添加目标 Wi-Fi

当前设备使用的配置文件是：

```text
/etc/wpa_supplicant.conf
```

打开文件：

```sh
vi /etc/wpa_supplicant.conf
```

**不要清空原文件，不要删除原有全局设置。** 保留原来的网络配置，在文件末尾添加：

```ini
network={
    ssid="C103"
    psk="替换为C103的真实密码"
    key_mgmt=WPA-PSK
    priority=10
}
```

填写说明：

- `ssid`：Wi-Fi 名称，大小写必须正确。
- `psk`：在你自己的终端中填写真实密码，不要把占位文字当作密码。
- 这份示例适用于普通 WPA/WPA2-Personal 密码网络，不适用于企业账号认证、网页认证或所有 WPA3-only 网络。
- 普通口令通常为 8～63 个字符；如果名称或密码含双引号、反斜杠，需要按 wpa_supplicant 语法转义，不能原样插入引号之间。
- `priority` 越大越优先；原网络未设置时通常按 0 处理。如果目标网络已经有配置块，修改原块，不要重复添加。
- 如果其他已保存网络的优先级更高，需要调整优先级。不要给多个同时可用的网络设置相同优先级后，假定一定连接其中某个。

### vi 保存方法

1. 按 `Esc`，确保退出输入模式。
2. 按大写 `G`，跳到文件末尾。
3. 按小写 `o`，新建一行并进入输入模式。
4. 输入配置，填写名称和密码。
5. 按 `Esc`，输入 `:wq`，回车保存退出。

如果不想保存本次编辑：按 `Esc`，输入 `:q!`，回车退出。

保存后限制配置文件权限：

```sh
chmod 600 /etc/wpa_supplicant.conf
```

**密码保护：** 不要把配置内容、终端密码截图或 Wi-Fi 密码发到聊天、提交到 Git、放进项目文档。不要将真实密码写在 shell 命令参数中，避免进入命令历史。

## 4. 重新读取配置并连接

逐条执行：

```sh
wpa_cli -i wlan0 reconfigure
wpa_cli -i wlan0 reassociate
```

正常应返回 `OK`。如果返回 `FAIL` 或无法连接控制接口，先停止后续操作，检查配置和服务，不要直接拔 USB。

等待约 10～20 秒，再执行：

```sh
wpa_cli -i wlan0 status
```

目标输出包含：

```text
ssid=C103
wpa_state=COMPLETED
```

**必须同时检查 SSID 和状态。** `COMPLETED` 仅代表无线关联/认证完成，不代表电脑一定能访问，也不代表已经取得正确的新 IP。

## 5. 获取新的无线 IP

当前设备已有 DHCP 客户端运行，并使用 `/run/udhcpc.wlan0.pid`。确认连接目标 Wi-Fi 后，让该客户端重新申请地址：

```sh
if [ -s /run/udhcpc.wlan0.pid ]; then
    kill -USR1 "$(cat /run/udhcpc.wlan0.pid)"
else
    echo "未找到 wlan0 DHCP PID 文件，请检查 DHCP 客户端，不要重复启动多个客户端"
fi
```

如果出现 PID 无效或进程不存在的错误，停止此步骤并检查 DHCP 客户端，不要盲目重试或另开多个实例。

等待几秒，再执行：

```sh
ip -4 addr show wlan0
ip route
```

例如看到：

```text
inet 192.168.1.120/24
```

说明荔枝派无线 IP 为 `192.168.1.120`。**这只是举例，请使用实际输出。**

如果状态显示 C103，但 IP 仍是旧网络的 `172.20.*`，不要据此测试成功；等待 DHCP 更新并排查。若无 IPv4 地址，则 DHCP 尚未成功。

## 6. 用无线 IP 验证 SSH

保留原 USB 终端，在笔记本上 **另外打开一个 PowerShell 窗口**：

```powershell
ssh root@192.168.1.120
```

将示例 IP 替换为实际无线 IP。能进入荔枝派终端，再执行：

```sh
hostname
ip -4 addr show wlan0
```

确认连接的是目标设备。

首次通过新地址登录时，SSH 可能要求确认主机指纹；应与通过 USB 确认的设备指纹核对。若提示主机密钥变化，不要直接关闭主机密钥检查或删除记录，应先核实是否 IP 被分给了其他设备。

成功标准：

1. 荔枝派显示 `ssid=C103`、`wpa_state=COMPLETED`。
2. wlan0 已取得目标网络地址。
3. 笔记本通过该无线 IP 成功 SSH 登录目标荔枝派。

即使 USB 此时还插着，使用无线 IP 建立的 SSH 连接也是对无线访问路径的验证。断开 USB、换充电宝后，还需要完成下一节的独立供电验收。

## 7. 改用充电宝与开机自动连接

当前板子的 `/etc/init.d/S30wifi` 已包含开机联网逻辑，`/boot/wifi.sta` 已存在，无须额外添加自启动脚本。

**配置来源注意事项：** 当前检查时未发现下面这些覆盖文件。以后如果出现，启动脚本可能使用它们重新生成或覆盖 `/etc/wpa_supplicant.conf`：

- `/boot/wpa_supplicant.conf`
- `/boot/wifi.ssid`
- `/boot/wifi.pass`

不要只修改 `/etc` 后就假定永久有效，也不要未经检查就删除 `/boot` 文件。当前启动脚本还可能输出 `/boot/wifi.pass` 中的密码，因此不推荐使用该文件保存新密码。

无线 SSH 验证通过后：

1. 正常停止录像及摄像头程序，等待清理完成。
2. 在荔枝派终端执行 `poweroff`，等待系统关机完成。
3. 断开电脑供电，改用稳定的充电宝和供电线。
4. 等待系统启动、自动连上 Wi-Fi。
5. 在路由器设备列表中查找新 IP，或使用之前的无线 IP 再次尝试 SSH。

> DHCP 地址可能改变。希望地址稳定时，优先在你有管理权限的路由器上设置 DHCP 地址保留，而不是随意给板子写死 IP。不要直接拔掉正在录像或写盘的设备电源。

## 8. 以后切换到其他环境

例如到另一个房间，电脑改连 `Room_WiFi`：

1. 保留或恢复 USB 登录通道。
2. 编辑 `/etc/wpa_supplicant.conf`，添加新网络块：

```ini
network={
    ssid="Room_WiFi"
    psk="替换为该网络的真实密码"
    key_mgmt=WPA-PSK
    priority=20
}
```

3. 重新执行第 4～6 节：加载配置、重新关联、更新 DHCP、查询 IP、无线 SSH 验证。

可以保留多个已知网络；同处可见时，优先级会影响选择。不要无限增大数值，定期按实际需求整理优先级即可。

## 9. 常见故障与恢复

| 现象 | 检查方向 |
|---|---|
| 仍连接 GDIP_WEB | 检查 C103 名称、密码、信号、配置是否被加载及网络优先级 |
| `reconfigure` 返回 `FAIL` | 检查大括号、引号、拼写、口令长度及配置语法；使用 USB 修正后再重试 |
| 一直认证失败或反复连接 | 密码错误、加密方式不兼容、信号不足，或接入点限制 |
| 已 COMPLETED，但没有 IPv4 地址 | 检查 DHCP 客户端、路由器 DHCP 和网络准入限制 |
| 两台设备看似同网段，SSH 却失败 | 检查访客/客户端隔离、防火墙、VPN 路由、IP 是否属于目标板子 |
| 端口测试成功，但 SSH 被关闭 | 不能单凭端口可达认定板子在线；检查 VPN、实际路由和 SSH 报错 |
| 重启后又连回旧 Wi-Fi | 检查优先级、目标网络是否可用，以及 `/boot` 配置覆盖来源 |
| 无线 SSH 正常，摄像头网页打不开 | 应使用无线 IP；另外检查程序监听地址、端口和防火墙，可能需要单独调整应用配置 |

笔记本上的只读排查命令：

```powershell
netsh wlan show interfaces
ipconfig
Test-NetConnection -ComputerName 192.168.1.120 -Port 22
```

最后一条要替换为实际无线 IP。查看详细输出中的接口和源地址，确认没有被 VPN 错误接管。不要为了排查直接关闭系统防火墙或修改全局网络配置。

### 配错了怎么恢复？

- 无线配置失败时，保持 USB 登录，使用 `vi` 修正或移除本次新增的网络块，不要清空整个配置文件。
- 因为保留了原网络块，可以调整它的优先级来恢复原来的选择。
- 修正后重新执行第 4～6 节，不需要重刷系统，也不需要修改摄像头程序。
- 如果是原配置被 `/boot` 文件覆盖，先确认实际生效来源，再处理；不要同时修改多个来源以免难以追踪。

## 10. 操作速查

```text
电脑连目标 Wi-Fi
  → USB SSH 登录荔枝派
  → vi /etc/wpa_supplicant.conf（添加目标网络，保留原配置）
  → chmod 600 /etc/wpa_supplicant.conf
  → wpa_cli -i wlan0 reconfigure
  → wpa_cli -i wlan0 reassociate
  → wpa_cli -i wlan0 status（确认目标 SSID + COMPLETED）
  → 通知现有 DHCP 客户端更新地址
  → ip -4 addr show wlan0
  → 电脑通过无线 IP SSH 登录
  → 正常关机、更换供电、再次验证无线登录
```

参考：[Sipeed 官方 LicheeRV Nano 外设与网络说明](https://wiki.sipeed.com/hardware/en/lichee/RV_Nano/5_peripheral.html)。本机实查的启动脚本优先用于判断当前镜像行为，不能将其他镜像的命令直接套用。
