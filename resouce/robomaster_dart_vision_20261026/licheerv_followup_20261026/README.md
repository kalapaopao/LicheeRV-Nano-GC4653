# LicheeRV Nano + GC4653：带识别算法到底多少帧？

补充检索日期：2026-10-26。本目录为后续补充，上一层的清单/验证报告仍代表上一轮快照，没有被覆盖。

## 最重要的结论

| 来源/方案 | 实际找到的帧率说明 | 能否作为“基地引导灯神经网络运行 FPS” |
|---|---|---|
| 北理工 2026-01-20 文章回顾的 Nano + GC4653 旧方案 | 1280×720、约 60 FPS；MicroPython，同时做 IMU 解算与运动控制 | **不能直接这样理解**：未明确模型结构、输入尺寸、推理耗时及帧率测量边界 |
| 哈工大威海 HERO 2026 | 图中明确 GC4653 + YOLO11n NPU，文字称满足控制需要 | **未公布具体数值**，无法填 30/60/80 FPS |
| 北理工 FPGA + OV9282 | 640×400、约 296.72 FPS，PL 流水线处理 | 不是 Nano + GC4653，也不是 YOLO 神经网络性能 |
| 你的当前项目 | README 记录约 80 FPS 采集链路 | 不是带模型的检测吞吐量，也不是端到端延迟 |

**因此，“他们的 Nano 带基地识别模型能跑多少帧”目前不能给出有证据的明确数值。** 之前的 60 FPS 回答只能描述北理工文中那套视觉/控制方案，不能进一步扩展为 YOLO11n 的实测帧率。

### 北理工原文证据

[1438280 原文](https://bbs.robomaster.com/article/1438280?source=4)，本地 `bit_1438280.html/.txt`。

读“AIOT芯片方案”和“方案对比”两节，能看到 Nano + GC4653、MicroPython、720P60fps 等描述；正文有一处把传感器写为 `CG4653`，同文其它位置及表格写 `GC4653`，这里按上下文判定为笔误，不当作另一个型号。

飞行时没有开启 Wi-Fi 图传是该旧方案的运行条件之一。没有在这段文字中发现具体神经网络权重、模型输入尺寸或逐帧计时数据。**60 FPS 不是硬件绝对上限，也不是已核实的 YOLO11n FPS。**

### HERO 原文与图像证据

[1884423 原文](https://bbs.robomaster.com/article/1884423?source=4)，本地 `hero_1884423.html/.txt`。

已下载并查看原文图片 `attachments/HERO_vision_pipeline.jpg`。图中能直接读到：GC4653、ISP+VPSS、裁剪/旋转90°/缩放、YOLO11n NPU推理、传统视觉阈值筛选、卡尔曼滤波、角度解算、UART、日志及 RTSP。

该图片确认了**同款相机与网络类型**，但没有 FPS、输入张量尺寸或量化配置。正文“实时性较好”不等于一个数值测试结果；图上有录像/推流也不证明在全功能同时开启时仍保持某个帧率。

## 建议如何推进

1. **最优先向 HERO 作者获取实际模型和输入参数**，否则无法复现其识别率和性能。
2. 即使拿到 `.onnx`，也先核对类别和预处理，再转换到 SG2002 支持的运行格式；不能把 `.pt` 直接拷上去就当作 NPU 模型。
3. 用同一批实拍视频分别测传统阈值基线和目标模型，独立统计采集 FPS、推理 FPS、带后处理吞吐量、P95 延迟和识别稳定性。
4. 通用 COCO YOLO11n 可以当作**性能基线**，但不是基地引导灯模型，不能据此验收基地识别。

可直接向作者询问：
